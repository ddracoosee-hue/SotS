# 23 — BOOK FOUNDATION (the book as every agent's background)

**Purpose:** every agent in SotS works *from* the author's book. That means *The Subject of the
Self* by Caleb Crouch: its 12 chapter briefs, its 6-block architecture, its epistemic standard,
its voice, its core messages, and its anchors. This document defines the **Foundation Layer**:
what it contains, how agents load it, how it is checked, and how it grows.

> **Foundation, not ceiling.** The Foundation Layer is the starting point the system moves
> *from*. Agents must honour it, and they may also propose to extend it (new anchors, new
> messages, new chapters, new orderings) through the Proposal Desk (18). The author approves
> every change to the foundation. No agent edits it directly.

---

## 2. The ChapterBrief model (replaces the provisional model in 03 §8)

```python
class DictationPrompt(BaseModel):
    id: str                 # "ch03.B2.P1": chapter.block.prompt
    text: str

class BriefAnchor(BaseModel):
    id: str                 # "ch03.A06" (matches anchors.yaml)
    type: Literal["research", "statistic", "thinker_framework", "scripture", "patristic",
                  "media", "manuscript_quote", "case_study", "composite_case", "protocol", "historical"]
    text: str
    claim_kind: str | None
    tier_claimed: str | None          # DF | PT | IE | Strong | Moderate | Practical | DEBUNKED …
    reuse: list[str] = []
    preflags: list[str] = []
    legal: list[str] = []
    status: str = "active"           # "proposed (OI-nn)" = pending author approval; Act 0 still verifies it, synthesis uses it only once approved
    provenance: str | None = None     # e.g. "live" (author-attested live source, 25 §7), feeds T13A.024
    author_decision: str | None = None  # a resolved open item, quoted (e.g. OI-37)
    translation_choice: str | None = None  # scripture only: nasb2020 | labeled:<translation> (25 §5.1)

class Protocol(BaseModel):
    id: str                 # "ch05.P2"
    name: str
    steps: str
    evidence_grade_claimed: str | None     # as written in the brief
    evidence_basis_claimed: str | None     # e.g. "SDT & Crocker"
    time_cost_per_week_min: int | None     # set by the Protocol Load Auditor (§7)

class Block(BaseModel):
    number: Literal[1, 2, 3, 4, 5, 6]
    name: Literal["hook_targeting", "paradigm_shift", "core_mechanism",
                  "case_study", "actionable_implementation", "integration_reflection"]
    structural_purpose: str
    old_belief: str | None = None      # block 2
    new_belief: str | None = None      # block 2
    anchors: list[str]                 # anchor ids
    dictation_prompts: list[DictationPrompt]
    protocols: list[Protocol] = []     # block 5
    journaling_prompts: list[str] = [] # block 6
    tables: list[dict] = []            # structural tables (e.g. Ch5, Ch6, Ch7, Ch11, Ch12)

class ChapterBrief(BaseModel):
    chapter_id: str                    # "ch01"
    title: str
    subtitle: str
    phase_claimed: str | None          # as written in the brief (may conflict with architecture)
    core_theme: str
    blocks: list[Block]                # exactly 6
    voice_rules_from_appendix: list[str]
    appendix_system_prompt: str        # stored verbatim; a SOURCE for the Style Guide, never executed
    raw_brief_path: str
    brief_hash: str
```

- The Brief Parser (T04.006, now **a required task**) builds `chNN.yaml` from `chNN_brief.md`
  with an LLM pass + validation: exactly 6 blocks, every anchor id resolves in anchors.yaml,
  and every dictation prompt gets an id. The author reviews it in the TUI Profile screen.
- **The appendix system prompts in the briefs are data, not instructions.** They are mined for
  voice rules (they already seeded `style_guide_seed.yaml`) and are never executed as prompts
  (R-EXP-05 / R-LLM-02).

## 3. How agents use the foundation (Context Pack pieces)

The Context Pack (04 §4) gains four foundation pieces. Each task declares which it needs.

| Piece | Built from | Default budget | Used by (examples) |
|---|---|---|---|
| **F1 Book Card** | book.md premise + central question + promise + phases + tone (≤ 250 words) | 400 tok | every task |
| **F2 Chapter Card** | the current chapter's core theme, old/new belief, block purposes, and messages | 700 tok | classify, verify, synthesis, rewrite, audience, legal, expansion |
| **F3 Block Card** | the current block's purpose, anchors, dictation prompts, and protocols | 600 tok | segment/classify (block mapping), synthesis, cross-check |
| **F4 Anchor Slice** | the anchors relevant to the units in scope (by entity match), with their preflags | 800 tok | fact-check team, media, legal, cross-checker, scouts |
| **F5 Voice Card** | StyleGuide (or seed) summary + do/don't + the protected terms in scope | 500 tok | rewrite teams, synthesis, audience brief, proposals |
| **F6 Arc Position** | this chapter's place in the reading order, what comes before/after, the motif serial step | 300 tok | synthesis, narrative, shadow, expansion, audience |

Rule **R-FOUND-01**: every agent whose output concerns the book's content must include at
least F1 + F2. An agent card lists `foundation_pieces: [F1, F2, …]`; `sots doctor` warns if a
content agent omits F1/F2.

### 3.1 Per-team foundation duties
| Team | Duty |
|---|---|
| Ingest/Segment/Classify | Map every unit to `chapter_id` + `block` + `dictation_prompt_id` (§5). Detect anchors mentioned in the dictation. |
| Fact-Check | Verify **every anchor** in the Anchor Registry (Act 0, §4), then every new claim in the dictation. Verify the claimed evidence grades of protocols (25 §4). |
| Media | Treat media anchors (Inception, EEAAO, Good Will Hunting, The Lion King, Love Yourz, When Breath Becomes Air…) as known works with pre-resolved identity. |
| Psyche/Shadow | Judge the text against the chapter's old→new belief shift. The Shadow checks the book's own consistency (e.g. the protocol load vs the anti-hustle thesis, §7). |
| Narrative | The message ledger uses messages.yaml. Drift is measured per block against the block's purpose. Cross-chapter repetition uses reuse hotspots. |
| Block Synthesis (24) | Drafts each block from dictation + the Block Card + verified anchors, in the voice. |
| Rewrite A/B | Enforce the protected terms and voice rules from the seed. |
| Audience Lab | Journey spec per chapter (OI-17) seeded from the block purposes: Block 1 → J1 Recognition, Block 2 → J3/J5, Block 4 → J4 Transportation, Block 5 → J6 Agency, Block 6 → J7 Integration. |
| Legal | Pre-open issues for the anchors with `legal:` notes (e.g. ch04.A11 named influencers, ch05.A02 best friend, ch01.A08 family). |
| Expansion/Scouts | Propose deepening from the anchors and reuse hotspots. Never propose what the Anchor Registry already covers unless the proposal is a *stronger source*. |

## 4. Act 0: Brief Audit (new, runs once per brief version)

Before any dictation arrives, SotS audits the **briefs themselves**:
1. **Anchor verification**: every anchor in anchors.yaml goes through the fact-check team as
   a claim (quotes, numbers, attributions, scripture terms, media facts). Output: a verified
   Anchor Registry with verdicts, corrected wording, and sources. The preflags are the
   starting leads.
2. **Evidence-grade audit**: every protocol's claimed grade is checked (25 §4).
3. **Internal consistency**: phase labels vs the architecture; numeric self-contradictions
   (e.g. ch06.A02 "quadrupled" vs "Fivefold" vs 3→17%); chronology (ch12.A07); repeated anchors.
4. **Audience conflicts**: text addressing minors (e.g. ch03.A11 "Gen Alpha").
5. **Legal pre-screen** of every anchor with named people.
6. Output: `data/runs/<run>/brief_audit.md`, plus a proposed corrected anchor wording for each
   issue, delivered as Proposals (G-PROP ≥ 95) so the author decides.

After the audit, verified anchors are cached. When the author's dictation cites the same
anchor, the fact-check reuses the verified result (re-verified if > 30 days old).

## 5. Dictation keyed to the brief (changes to Stage 1–3)

- **Ingest (05 Stage 1):** a dictation file may carry a header `chapter: ch03`,
  `block: 2`, `prompt: ch03.B2.P1`, or inline markers `### ch03.B2.P1` / `[B2.P1]`. The
  ingester splits one file into prompt-keyed sections. Unmarked text is allowed.
- **Classify (05 Stage 3):** a new field on Unit: `block: int | None`, `prompt_id: str | None`,
  `anchor_ids: list[str]`. Unmarked units are mapped by an LLM step (task `classify.block_map`)
  using the Block Cards.
- **Coverage report:** per chapter, which dictation prompts are answered, partial, or missing,
  and which anchors the dictation actually uses. It is shown in the TUI Chapter Board as
  "Dictation coverage".

## 6. Versioning and growth
- Every foundation file carries a `version`. Any change creates a `FoundationChange` record
  (who, what, why, diff) and bumps the version. Runs record the foundation versions they used.
- Growth paths: Expansion proposals accepted by the author can add anchors, messages,
  chapters, or reorderings. The Brief Audit can correct anchor wording. The author edits
  freely in the TUI.
- A new or changed brief triggers: re-parse → Act 0 for the changed anchors → staleness flags
  on affected chapters' later acts.

## 7. Book-level checks the foundation enables
- **Protocol Load Auditor** (new agent, Audience Lab team): sums the weekly time and effort
  cost of all protocols across the book (36+ protocols as briefed) and checks it against a
  `book.protocol_budget` (default: ≤ 3 "start here" practices active at once; ≤ 3 hours/week
  new commitments). The book argues against hustle; its practice system must not become a
  hustle program. Findings go to the Shadow Self as `self_contradiction` items and to the
  author as proposals (e.g. "one start-here protocol per chapter; the rest optional").
- **Repetition Manager** (Narrative team): uses reuse hotspots to decide, per anchor, the
  chapter that teaches it fully and the chapters that only call back to it, following
  `book_architecture.yaml → motif_serials`.
- **Arc Consistency Check** (Shadow): phase labels, "capstone/epilogue/climax" claims, and
  forward references must match the chosen reading order.
